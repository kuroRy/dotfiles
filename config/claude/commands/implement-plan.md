承認済みの実装計画に従って実装してください: $ARGUMENTS

**このコマンドの起動をもって、コミットおよびプルリクエスト作成の承認とみなします。** ただし PR は draft として作成し、レビュー依頼は人間が行います。

`$ARGUMENTS` が空の場合は、計画ファイルのパスを尋ねて停止してください。

## 1. 計画の読み込み

1. 計画ファイルを読む。記載された前提・設計判断・実装ステップを把握する
2. 「未確認事項」の節に未解決の項目が残っている場合は、実装に入らず内容を提示して確認を取る

## 2. 実装

3. 作業ブランチが未作成なら、既定ブランチから計画に沿った名前（例: `fix/<issue番号>-<slug>`）で切る
4. 計画の「実装ステップ」の順に実装する。**計画から外れる必要が生じたら、実装を止めて計画の修正を提案する**
5. 計画に記載された品質管理手順（Linter / Formatter / 型チェック / テスト）を実行する
6. 計画に記載された動作確認手順を実行する。実行できないものは「未実施」と理由を明示する

## 3. 提出

7. 変更をコミットする。関連 issue があればメッセージ本文に `Refs #<issue番号>` を含める。**計画ファイル自体をコミットに含めるかはリポジトリの方針に従う。方針が不明なら含めない**
8. `git push -u origin <ブランチ名>` の後、`gh pr create --draft` でプルリクエストを作成する。base はリポジトリの既定ブランチとし、説明欄に以下を記載する
   - 計画ファイルへのリンクまたはパス
   - 関連 issue へのリンク
   - 計画から逸脱した点があればその内容と理由
9. 品質チェックと動作確認の結果を報告する。**失敗したものや未実施のものは省略せずに明示する**
