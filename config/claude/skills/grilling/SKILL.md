共通理解に到達するまで、ユーザーを徹底的にインタビューする。これを **design tree（設計ツリー）** として捉える。すべての判断は、そこにぶら下がる下位の判断へと枝分かれしていく。

ツリーは **ラウンド** 単位で処理する。**frontier（フロンティア）** とは、前提となる判断が既に確定している判断すべて、つまり **まだ聞いていない答えを推測せずに今すぐ聞ける質問** の集合を指す。フロンティア全体を1ラウンドでまとめて問う。各質問に番号を振り、推奨する回答を添える。そのうえでユーザーの回答を待ってから次のラウンドへ進む。

ラウンドは次の形式で提示する。

```
❓ **Q1** - **<質問のタイトル>**: <質問の本文。複数段落でもよく、選択肢を含めてもよい>

➡️ <推奨する回答>

---

❓ **Q2** - **<質問のタイトル>**: <質問の本文。複数段落でもよく、選択肢を含めてもよい>

➡️ <推奨する回答>
```

ユーザーが回答するたびにツリーは組み替わる。確定した判断がフロンティアを外側へ押し広げ、それに依存していた質問が解禁される。フロンティアを再計算し、次のラウンドを問う。**同じラウンド内でまだ未解決の質問に答えが依存する質問は、そのラウンドではなく後のラウンドに属する。**

**事実** を突き止めるのは常に自分の仕事であり、ユーザーの仕事ではない。フロンティア上の質問が環境（ファイルシステム、ツールなど）から得られる事実を必要とする場合は、サブエージェントを派遣して調べさせる。**自分で調べられることをユーザーに尋ねてはならない。** ただしそこでブロックしない。実行中の調査は未確定の前提にあたるので、そのサブエージェントの報告を待つのはその下流にある質問だけであり、残りのフロンティアは今すぐ問う。**判断** はユーザーのものである。一つひとつをユーザーに提示し、回答を待つ。

セッションが完了するのは、フロンティアが空になったときである。設計ツリーのすべての枝を訪れ、暗黙のまま放置された前提が一つもない状態を指す。共通理解に到達したことをユーザーが確認するまで、その内容に基づいて行動してはならない。
